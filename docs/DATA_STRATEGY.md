# 📊 부동산 이상 거래 탐지 시스템: 투트랙(Two-Track) 데이터 전략

본 프로젝트는 머신러닝 시스템의 실무 모범 사례(Best Practice)를 따라, **과거 데이터(Batch)와 실시간 데이터(Streaming)**를 완벽하게 분리하여 수집 및 활용합니다. 팀원들은 이 문서에 명시된 기준에 따라 각자의 코드를 개발해야 합니다.

---

## 1. 📂 CSV 기반 정적 데이터 (Batch & Training 용)

Autoencoder 모델이 "정상적인 아파트의 패턴"을 탄탄하게 학습(Training)하기 위한 대용량 베이스라인 데이터입니다.

*   **수집 방법**: 공공데이터포털, 국토교통부, K-apt 홈페이지에서 통째로(Dump) 엑셀/CSV 다운로드
*   **기간**: **최근 3~5년 치** 시계열 데이터
*   **활용처**: 초기 AI 모델 학습 (Training) 및 군집화(Clustering) 기준점 설정
*   **상세 수집 항목**:
    *   과거 3~5년간의 실거래가 이력 전체
    *   월별 관리비 항목 통계 (장기수선충당금 잔액 추이, 수선비 지출 내역 등)
    *   단지 상세 재원 (총 세대수, 준공 연식, 주차 대수 등 변하지 않는 정적 데이터)
*   **저장 위치**: `.gitignore` 처리된 `data/raw/` 폴더 내부에 직접 저장
*   **담당자**: 팀 리드 (직접 다운로드 및 Pandas로 병합)

---

## 2. 📡 API 기반 동적 데이터 (Real-time & Inference 용)

학습이 끝난 모델이 "방금 발생한 거래가 이상한가?"를 실시간으로 판독(Inference)하고, n8n을 통해 텔레그램 알림을 쏘기 위한 라이브 센서입니다.

*   **수집 방법**: 파이썬 `requests` 모듈 등을 활용해 국토부, K-apt, 네이버 Open API 호출
*   **기간**: **당월(최근 1개월) 또는 최신(Latest)** 데이터만 스니핑
*   **활용처**: 라이브 모니터링 시스템에서의 실시간 추론 (Inference), 비정형 리스크 필터링
*   **상세 수집 항목**:
    *   **당월 실거래가 신고 내역**: 오늘 갱신된 새로운 거래 건수
    *   **이번 달 관리비 공고 내역**: 해당 거래가 발생한 단지의 가장 최신 관리비/장충금 상태
    *   **최신 뉴스 헤드라인/본문**: 거래 시점 기준 당일/주간의 단지 관련 뉴스 (KoBERT 실시간 감성 분석용)
*   **수집 파이프라인**: n8n 스케줄러가 매일 주기적으로 API 수집 파이썬 스크립트를 트리거
*   **담당자**: 손종인 (API 크롤러 개발 시 파라미터를 '당월/최신'으로 고정할 것)

---

## 3. ⚙️ 데이터 흐름도 (Data Flow)

```text
[과거 5년치 CSV 다운로드] ──▶ (Pandas 전처리) ──▶ [Autoencoder 모델 학습(Train)]
                                                        │
                                                        ▼
[n8n 스케줄러 매일 작동] ──▶ (API로 당월 데이터 수집) ──▶ [이상치 실시간 판독(Inference)] ──▶ (텔레그램 경고 알림)
```
